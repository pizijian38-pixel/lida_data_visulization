# 图表评估标准

移植自 LIDA `lida/components/viz/vizevaluator.py`。原版只看代码打分；这里要求你**同时看渲染出的 PNG**。

## 6 个维度（每项 1–10 分）

| 维度 | 检查什么 | 硬性规则 |
|---|---|---|
| **bugs** 缺陷 | 有没有逻辑错误、错误的列、错误的聚合（例如对比率求和）、转换遗漏（文本数字没转换）、静默丢数据（过滤掉大量 NaN/NaT 却没说明）？ | 存在任何缺陷时必须 < 5 分 |
| **transformation** 数据转换 | 数据有没有被正确地过滤、聚合、分组？时间粒度合适吗？Top N 合理吗？ | |
| **compliance** 目标符合度 | 图能不能直接回答 goal 里的 question？用户的每个要求（筛选条件、时间范围、单位、指定的图表类型）都满足了吗？ | |
| **type** 图表类型 | 按 `chart_selection.md` 的最佳实践，这是最合适的图表类型吗？ | 有明显更合适的图表类型时必须 < 5 分 |
| **encoding** 数据编码 | x、y、颜色、大小的映射正确吗？排序合理吗？柱状图从 0 开始吗？颜色有意义吗？ | |
| **aesthetics** 美观可读 | 看 PNG：文字有没有重叠或被截断？有没有方块字？图例有没有遮挡数据？标题、单位清楚吗？数字格式易读吗？留白合适吗？ | 图上出现方块字或文字重叠时必须 < 6 分 |

## 看 PNG 时逐项检查

- [ ] 所有中文都正常显示，没有 □□□
- [ ] 刻度标签没有重叠，也没有被裁掉
- [ ] 图例没有挡住数据，图例项不超过 12 个
- [ ] 数字带单位，并且格式易读（千分位 / 万 / %）
- [ ] 不是空图，也没有出现明显异常（例如一根柱子极高而其余几乎看不见，这时考虑对数刻度或拆图）
- [ ] 标题能概括图的内容

## 输出格式（写在你的思考里，不必展示给用户）

```json
[
  {"dimension": "bugs", "score": 9, "rationale": "..."},
  {"dimension": "transformation", "score": 8, "rationale": "..."},
  {"dimension": "compliance", "score": 9, "rationale": "..."},
  {"dimension": "type", "score": 9, "rationale": "..."},
  {"dimension": "encoding", "score": 8, "rationale": "..."},
  {"dimension": "aesthetics", "score": 6, "rationale": "x 轴 18 个月份标签重叠"}
]
```

## 修复（LIDA 的 repair）

任一维度低于 7 分，或者 render.py 返回了 `warnings`：
1. 把低分维度的 rationale 当作修复指令。
2. **只修改 `plot()` 内部**，保持模板结构不变，然后重新渲染。
3. 最多修复 2 轮。2 轮后仍有问题，就交付当前最好的版本，并告诉用户剩下的问题。
