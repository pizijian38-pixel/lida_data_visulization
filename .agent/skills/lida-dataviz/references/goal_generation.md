# 可视化目标（goal）生成

移植自 LIDA `lida/components/goal.py` 和 `persona.py`。

## 目标格式

```json
[
  {"index": 0,
   "question": "各大区的月度销售额走势如何？哪个大区增长最快？",
   "visualization": "折线图：x=日期(按月), y=销售额（元）求和, 颜色=大区",
   "rationale": "用「日期」「大区」「销售额（元）」三列。按月汇总后比较各大区的走势和斜率，能看出增长差异。"}
]
```

- `question`：要回答的业务问题
- `visualization`：图表类型 + 编码方式，**必须引用摘要 `field_names` 里的确切列名**（包括全角括号等字符）
- `rationale`：为什么用这些列，以及能从图里学到什么

## 情况 A：用户给出了明确需求

1. 找出需求里的**度量**（要看的数字）、**维度**（按什么拆分）、**时间范围/筛选条件**。
2. 把它们映射到具体列名。映射不唯一时（比如有「销售额」和「含税销售额」），选更常用的那列并在交付时说明；如果选错会让结论完全不同，就问用户。
3. 需求里隐含的计算要写进 visualization，例如"同比增长率""占比""Top 10"。

## 情况 B：用户没有具体需求（探索式分析）

按 LIDA 的原始指令生成 3–5 个目标：

> 你是一位经验丰富的数据分析师，根据数据摘要和指定的 persona 生成指定数量的、有洞察力的目标。
> 推荐的可视化**必须遵循可视化最佳实践**（例如比较数量时用柱状图而不是饼图），并且**有意义**（例如经纬度应画在地图上）。
> 目标必须和 persona 的关注点相关。每个目标都要包含 question、visualization（必须引用摘要里的确切列名）和 rationale（说明为什么用这些列、能学到什么）。

**persona**（用户角色）：用户提到身份（"我是运营""给老板看"）时，从这个角色的视角出发。
没提到时默认用："一位能提出复杂、有洞察力问题的资深数据分析师"。

覆盖不同的问题类型，不要都是同一类：

| 优先级 | 问题类型 | 什么时候适用 |
|---|---|---|
| 1 | 趋势 | 有日期列或年份列 |
| 2 | 比较 / 排名 | 有类别列 + 数值列 |
| 3 | 构成 | 存在有意义的"整体-部分"关系 |
| 4 | 分布 | 关键数值列（看偏态、离群值） |
| 5 | 关系 | 两个以上数值列，并且相关性有业务意义 |

列出候选让用户选择时的格式：

```
1. 【趋势】各大区月度销售额走势 —— 折线图
2. 【排名】各品类累计销售额排名 —— 横向条形图
3. 【关系】销量与毛利率的关系 —— 散点图（按品类着色）
```
